Opciones del Instructor (Modo Dios) Inyección de Fallos de Red en Caliente (Troubleshooting)
Fallo 1 Desconectar cable virtual

Equivale a desmarcar "Cable conectado" en las opciones avanzadas de red de VirtualBox para la VM objetivo. Al ejecutar ping, devuelve inmediatamente Network is unreachable.

Estado: Cable conectado (Nominal)
Fallo 2 Regla DROP en iptables / Firewall

Inyecta una regla iptables -A INPUT -p icmp -j DROP (o Firewall de Windows) en la VM objetivo. Aunque el enlace físico exista, cualquier ping hacia o desde ella sufre Request timed out (100% pérdida).

Estado: Firewall ICMP permisivo (Nominal)
Fallo 3 MAC Duplicada / Conflicto de IP (Puente)

Fuerza a dos VMs en Adaptador Puente a compartir la misma IP (192.168.1.150) y colisión ARP/MAC, provocando caídas aleatorias de paquetes (packet loss intermitente y paquetes DUP!) en el ping.

Estado: Sin colisiones IP/ARP (Nominal)

Acerca de VirtLab — Simulador Completo (Fases 1 a 9)

VirtLab — Simulador de Oracle VM VirtualBox

Aplicación educativa desarrollada en Vanilla JavaScript (ES6+), HTML5 y CSS3 puro sin dependencias de backend, lista para desplegar en GitHub Pages.

  • Fase 1: Interfaz Skeumórfica/Desktop, Clase VirtualMachine, Asistente de creación ("Nueva") y Persistencia en LocalStorage.
  • Fase 2: Configuración de los 4 Adaptadores de Red (NAT, Adaptador Puente, Red interna y Adaptador sólo-anfitrión) + Clase NetworkEngine.
  • Fase 3: Ventana de Consola Interactiva (TTY Linux / CMD Windows) con soporte para ip a, ipconfig y ping [IP] con reglas estrictas de enrutamiento.
  • Fase 4: Panel Opciones del Instructor (Modo Dios) para inyectar fallos en caliente (Desconectar cable, Regla DROP en Firewall/iptables, y Conflicto de MAC/IP en Puente) + Botón de Restauración del Laboratorio.
  • Fase 5: Estado Compartible (Escenarios por URL) mediante exportarEscenario() y cargarEscenario() en window.onload usando Base64 (btoa() / atob()) en el parámetro ?escenario=.
  • Fase 6: Motor DHCP Interactivo (Proceso DORA) en terminal mediante dhclient (Linux) e ipconfig /renew (Windows) con retrasos simulados (DHCPDISCOVER, DHCPOFFER, DHCPREQUEST, DHCPACK) y timeout si el cable está desconectado.
  • Fase 7: Reenvío de Puertos (Port Forwarding) exclusivo del modo NAT + Consola del Anfitrión con soporte para curl localhost:[Puerto_Anfitrión] (respuesta HTTP/1.1 200 OK - Apache Server on [VM] o Connection refused).
  • Fase 8: Implementación de traceroute [IP] / tracert [IP] con saltos lógicos de 500ms por línea según el modo de red y latencias aleatorias entre 1ms y 50ms.
  • Fase 9: Motor de Retos y Flags (Modo CTF) mediante listener silencioso en el procesador de comandos y checkCTFWinCondition() extensible (soporta ufw allow icmp, desactivación de firewall por UI/consola y validación de ping 8.8.8.8 entregando [+] RETO COMPLETADO. Flag: flag{v1rtu4l_n3tw0rk_m4st3r}).
